AUDIT BUILDER - SETUP AND USE
=============================

Audit Builder replaces the old Audit.xlsm file. It runs in your web browser
(Chrome or Edge), but nothing is uploaded anywhere: the app only reads and
saves files on your computer and in this shared folder.


ONE-TIME SETUP (about 5 minutes)
--------------------------------

1. Install Google Drive for desktop
   - Download it from https://www.google.com/drive/download/
   - Sign in with the Google account the Audit Builder folder was shared with.
   - A "Google Drive" drive (usually G:) appears in File Explorer.

2. Put the shared folder on your G: drive
   - Open drive.google.com and go to "Shared with me".
   - Right-click the "Audit Builder" folder > Organize > Add shortcut,
     and choose My Drive.
   - After a minute it appears in File Explorer at
     G:\My Drive\Audit Builder

3. Make it work without internet (recommended)
   - In File Explorer, right-click the Audit Builder folder >
     Offline access > Available offline.

4. Make a desktop shortcut
   - Open G:\My Drive\Audit Builder, right-click AuditBuilder.html >
     Send to > Desktop (create shortcut).
     (On Windows 11, click "Show more options" first to see "Send to".)
   - Always open the app from this shortcut.
   - Do NOT copy AuditBuilder.html to your desktop or anywhere else.
     A copy doesn't get updates.

5. Use Chrome or Edge. (Firefox works too, but there "Save project"
   downloads a new copy each time instead of updating the same file.)


OPENING THE APP
---------------

Double-click the desktop shortcut. It opens in your browser.

If it opens in Notepad or shows code instead: right-click AuditBuilder.html >
Open with > Google Chrome (or Microsoft Edge), and tick "Always use this app".

Open it from File Explorer (the G: drive), not from the Google Drive website.
The website can't run the app and only shows its code.


UPDATES
-------

Updates are automatic. When a new version is published, Google Drive
replaces AuditBuilder.html in the folder, and you get it the next time you
open the app (or press F5 if it's already open). Your current work is kept.

The version (date and time) is shown at the top left of the app, next to its
name, in case you want to check you have the latest one.


THE MENUS
---------

The menu bar at the very top works like in a Windows program:
- File: New project, Open..., Save project (Ctrl+S), Save as... (Ctrl+Shift+S)
- Settings: Dictionary..., DevMode...
- Tools: Microsoft BIOS passwords... (see below)
The sun / moon button next to Tools switches between light and dark.
Under the menus: the project (click it to change the project setup), the
Output picker (Shuru or SIMS) and whether the project is saved.


DOING A PROJECT
---------------

1. New project: choose File > New project and fill in the project number, end client and
   item code prefix (for example GG; leave it empty if the item codes are
   just numbers) and the first item number (usually 1; e.g. 4000 if the
   client numbers from there).
2. Data tab (everything the report is built from): click "Add files..." and
   choose the Blancco exports (.csv, .xlsx or .zip). You can choose several
   at once or drag them onto the box. Paste the Mac and Windows report
   lines together in "Mac and Windows reports", in any order.
3. Manual entries tab (devices the tools couldn't read: dead, BIOS locked,
   no report...): click "Add item" and type the details. To add many at
   once, fill in "or items ... to ..." (e.g. 10 to 20) and click "Add range";
   items that already have a manual entry are skipped.
4. Review tab (check everything is right, make small corrections): every
   check is listed at the top. The Review tab button shows how many there
   are: red = problems, yellow = warnings, gray = notes. Rows with a problem
   are highlighted, and clicking a check jumps to its row. Edited cells turn
   blue, and clearing a cell (Delete) goes back to the calculated value.
   Diagnostic codes (like LM or CD) work in the Diagnostics and Locked or
   Faulty cells too.

The Review and Manual entries tables work like a spreadsheet:
   - Click a cell, or move with the arrow keys, Tab, Enter, Home / End,
     Page Up / Page Down. Ctrl + arrow jumps to the end of the filled cells,
     or to the next filled cell (like Excel).
   - Select several cells by dragging, Shift + click or Shift + arrows.
     Click a column header to select the column, Ctrl+A selects everything.
   - Start typing to replace a cell, or double-click / F2 to change it.
     Enter or Tab saves, Esc cancels.
   - Ctrl+C copies, Ctrl+X cuts, Ctrl+V pastes (also a block of cells copied
     from Google Sheets or Excel). One copied value pasted onto a selection
     fills all of it.
   - Delete clears the selected cells, Ctrl+D fills down.
   - Ctrl+Z undoes, Ctrl+Y redoes.
   The item code columns can be selected and copied but not changed.
   Green cells are values from the Google Sheet rows (Data tab); they can
   be changed like any other cell.
5. Export (the "Export..." button on the Review tab, only for getting the
   finished report out): click "Copy rows" and paste into the Google Sheet.
   If there are locked or faulty devices, copy that list too. Untick
   columns the Google Sheet doesn't have. If problems (red) are still open
   on Review, the app asks before opening Export.

Review and Export show a row for every item number from the first item
number up to the highest one. Numbers with no data yet get an empty (yellow)
row, so the rows line up with the Google Sheet; typing in one on Review adds
a manual entry. The "No data yet for" warning jumps to the first one.
"Hide empty rows" only hides them from view: Copy rows and the Excel file
always include them.

If some items are already in the Google Sheet (for example BM20 was typed in
by hand):
   a. In the Google Sheet, select the rows you'd paste over (from the first
      item row down past the last filled row, same columns as the export)
      and copy them.
   b. Paste them in "Rows already in the Google Sheet" on the Data tab. It is
      saved with the project.
   c. The sheet's values are used like any other input, but last in line:
      for every cell, Blancco, the Mac / Windows reports and manual entries
      win if they have a value; if they leave it empty, the sheet's value
      stays. Values that came from the sheet are green on Review. An item
      that is only in the sheet is a normal row.
   d. You can change them like anything else: a manual entry or a Review
      edit wins over the sheet. Any problem (for example no item codes
      found) is listed on the Review tab.
   e. In Export (button on Review) click "Copy rows", click the ITEM cell of
      the first item row in the Google Sheet and paste. The sheet's values
      are included, so they aren't lost (formulas become plain values).


SIMS PROJECTS (A DIFFERENT SHEET LAYOUT)
----------------------------------------

Some contractors (SIMS) want their own sheet instead of ours. The data and
the Manual entries stay exactly the same; only the output changes.

1. Set "Output" to SIMS. It is in the top bar next to the project name
   (always there), and also on the Review tab and in the Export window.
   It is saved with the project; switch back to Shuru any time.
2. The Review table then shows the SIMS columns D (Item No) to T (Blancco
   Result): Category (from the device type), Model (make, model, screen,
   year), Purchase Description (CPU, RAM, disk, or n/a), our Diagnostics,
   the SIMS Diagnostic Codes, Item Remark, Weight and Blancco Result
   (Erased / Not Erased).
   - Serial No, asset tag, Diagnostics and Weight are the same as in the
     Shuru layout: changing them changes both.
   - Typing in another column (e.g. Category or Diagnostic Codes) only
     changes the SIMS output. Clear the cell to go back.
3. Diagnostic codes: each diagnostic becomes the SIMS code of the device's
   category (e.g. "Sticky kb" on a laptop is LPT107). A diagnostic with no
   SIMS code goes to Item Remark and the device gets the "see remarks" code
   (e.g. LPT172). Review lists those as blue SIMS notes, so you can add them
   to the Dictionary. "Ok" is left out.
4. Export (button on Review) has three lists: Item per service project
   (paste at the Item No cell, column D, of the first item row), HDD (one
   row per data carrier serial from "S.N. Data carrier") and Locked and
   Faulty. "Download SIMS .xlsx" fills the SIMS template with the rows,
   so their logos, comments and Summary stay as they are; the Summary
   counts itself when you open the file. The template is
   G:\My Drive\Audit Builder\Templates\SIMS.xlsx. When SIMS sends a new
   template, empty it of data and save it over that file.
5. Rows already in the SIMS sheet can be pasted in "Rows already in the
   Google Sheet" on the Data tab (copy columns D to T), like for our sheet.

The SIMS lists are in the Dictionary (after "SIMS output:"):
- SIMS diagnostics: one row per SIMS issue. Write our diagnostics next to
  the issue they mean, separated by commas (e.g. "Sticky kb, KB sticky" next
  to keyboard defect). Capitals, spaces and dashes don't matter, and *
  stands for any word(s): "Key * defect" covers Key P defect, Key Capslock
  defect and so on. One issue
  works for every category: keyboard defect is LPT107 on a laptop and would
  be BSU107 on a PC. Writing a diagnostic on two issues gives two codes
  (BIOS locked = password protected + no audit). The first row, "Leave out",
  lists diagnostics that get no code at all (Ok). Use the search box and
  "Only issues with our diagnostics" to find your way in the list.
- SIMS codes: all SIMS codes per category (from their template), with a
  category filter and search.
- SIMS categories: which SIMS category each of our device types is, and,
  when it's different, which category's codes it uses (Switch uses Network
  Switch codes, loose disks use Data Carrier codes).


SAVING AND SHARING PROJECTS
---------------------------

- The app keeps your current work automatically, so closing the window by
  accident doesn't lose anything. That copy only exists on your computer
  and in that browser, though.
- File > Save project (or Ctrl+S): the first time, it asks where to save the
  project file (named after the end client and project number, e.g.
  Acme_SHR11734.audit.json).
  After that it saves over the same file without asking. The top bar shows
  which file you're saving to.
- After reopening the browser, the first save may show a small "allow this
  site to edit the file?" message. Click Allow (or "Edit file").
- File > Save as... (Ctrl+Shift+S) saves to a different file, which becomes the
  one used from then on.
- Opening a project file with File > Open... also makes it the file that Save
  updates. Starting a "New" project asks again on the first save.
- Save project files in G:\My Drive\Audit Builder\Projects. Google Drive
  syncs them, so everyone can open them with "Open...", and continue each
  other's projects. (This needs edit access to the shared folder; if saving
  there fails, ask Tomer to give you Editor access.)
- If two people work on the same project at the same time, their changes
  don't merge. Agree who has it.
- An old Audit.xlsm can be opened with "Open..." too.


SHARED DICTIONARY AND RULES
---------------------------

Everyone shares two files in the Audit Builder folder on the Drive:
- Models\models.json: the Dictionary (Settings > Dictionary...): models, make names,
  type mapping, weights, model cleanup, diagnostic codes and the SIMS lists. "Make names"
  turns the make the tools report into the one in the report, e.g.
  "Dell Inc." into "Dell".
- Config\config.json: the rules the report is built with (battery grades,
  how Blancco comments are read, which checks show on Review, column
  headers...), so everyone's report comes out the same.

Connect once (the browser only lets the app use files you picked yourself):
click "Connect folder..." in the yellow bar under the tabs and choose the
folder G:\My Drive\Audit Builder. The browser asks to let the app view and
edit files in it: allow it. The app then finds both files by itself.

After that:
- The app loads both every time it opens. Nothing more to do.
- After restarting the browser, a yellow bar may ask for your OK to load
  them. Click "Load shared files". If the browser offers "Allow on every
  visit", choose it and it won't ask again.
- Any change you make in the Dictionary is saved to the shared file, and
  coworkers get it the next time they open the app or switch back to it.
- If you and a coworker change the Dictionary at the same moment, the app
  keeps their version and asks you to redo your last change.

If the Dictionary window says "Not shared", your changes stay on your computer
only. Connect the folder as above.

Settings > DevMode... is for the person who maintains the rules and asks for
a password.


MICROSOFT BIOS PASSWORDS (Tools menu)
-------------------------------------

For Microsoft devices that are BIOS locked: Microsoft sends a file like
BulkBiosPasswordDetails-29065708.txt with the asset tag and password(s) of
each device.

1. Open the project, then Tools > Microsoft BIOS passwords...
2. Click "Load password file..." (or drop the .txt file in the window).
3. The list shows every asset tag in the file with its item number, S.N.
   and device from the project, items first (by item number), then asset
   tags that aren't in the project. Some devices have more than one
   password; each gets its own column.
4. Click a device (or move with the arrow keys) and its password appears
   as a QR code on the right, ready to scan into the BIOS. "Copy" copies
   the password.
5. Search finds an item, asset tag or S.N.; "Only devices in this project"
   hides the rest. "Copy with headers" and "Download .xlsx" give you the
   list as a sheet.
A yellow note lists items that are BIOS locked in the project but have no
password in the file.
The passwords are NOT saved with the project: load the file again next time.
