AUDIT BUILDER - SETUP AND USE
=============================

Audit Builder replaces the old Audit.xlsm file. It runs in your web browser
(Chrome or Edge), but nothing is uploaded anywhere: the app only reads and
saves files on your computer and in this shared folder.


ONE-TIME SETUP (about 5 minutes)
--------------------------------

1. Install Google Drive for desktop
   - Download it from https://www.google.com/drive/download/
   - Sign in with the Google account the Audit Builder folder was shared with.
   - A "Google Drive" drive (usually G:) appears in File Explorer.

2. Put the shared folder on your G: drive
   - Open drive.google.com and go to "Shared with me".
   - Right-click the "Audit Builder" folder > Organize > Add shortcut,
     and choose My Drive.
   - After a minute it appears in File Explorer at
     G:\My Drive\Audit Builder

3. Make it work without internet (recommended)
   - In File Explorer, right-click the Audit Builder folder >
     Offline access > Available offline.

4. Make a desktop shortcut
   - Open G:\My Drive\Audit Builder, right-click AuditBuilder.html >
     Send to > Desktop (create shortcut).
     (On Windows 11, click "Show more options" first to see "Send to".)
   - Always open the app from this shortcut.
   - Do NOT copy AuditBuilder.html to your desktop or anywhere else.
     A copy doesn't get updates.

5. Use Chrome or Edge. (Firefox works too, but there "Save project"
   downloads a new copy each time instead of updating the same file.)


OPENING THE APP
---------------

Double-click the desktop shortcut. It opens in your browser.

If it opens in Notepad or shows code instead: right-click AuditBuilder.html >
Open with > Google Chrome (or Microsoft Edge), and tick "Always use this app".

Open it from File Explorer (the G: drive), not from the Google Drive website.
The website can't run the app and only shows its code.

The app always opens on Project setup, like File > New project. From there:
- "Continue where you left off" opens the project you last worked on, as you
  left it (it says if that was a shared project, or if it has changes not
  saved to its file yet).
- "Open a project..." shows the project list (like File > Open).
- Or fill in the form and click Save to start a new project.
Starting a new project or opening another one asks first if the last
project has changes that aren't saved to its file.
File > New project shows this same window at any time ("Continue where you
left off" then goes back to the project that was open).


UPDATES
-------

Updates are automatic. When a new version is published, Google Drive
replaces AuditBuilder.html in the folder, and you get it the next time you
open the app (or press F5 if it's already open). Your current work is kept:
click "Continue where you left off".

The version (date and time) is shown at the top left of the app, next to its
name, in case you want to check you have the latest one.

The first time you open the app after an update, a "What's new" window lists
what changed: every update since you last opened it, newest first (if you
missed many, the older ones are folded at the bottom). Help > What's new
shows the list again any time.

If something unexpected goes wrong, a red message at the bottom says
"Something went wrong: ...". Click "Copy details" and send that text to whoever
looks after Audit Builder, so they can see exactly what happened.


THE MENUS
---------

The menu bar at the very top works like in a Windows program:
- File: New project, Open..., Save project (Ctrl+S), Save as... (Ctrl+Shift+S),
  Share project... (see "Working on a project together")
- Settings: Dictionary..., DevMode...
- Tools: Shared Files, PDF merger and Microsoft BIOS passwords (see below)
- Help: How to use Audit Builder (this guide, inside the app) and What's new
The sun / moon button next to Help switches between light and dark.
Under the menus: the project (click it to change the project setup), the
Output picker (Shuru, SIMS or Google) and whether the project is saved. Each
output has its own color (Shuru blue-grey, SIMS royal blue, Google green): the
whole Final Report tab, the picker and a "... layout" tag take it, so
you can see at a glance which layout you are copying.
Keyboard: Alt+1 Data, Alt+2 Manual entries, Alt+3 Final Report, Alt+4 BIOS passwords
(the number keys above the letters, not the number pad).
Alt+S jumps to the search box of whatever is in front (a tab, an open window,
or a column filter), so you can start typing at once.


DOING A PROJECT
---------------

1. New project: choose File > New project and fill in the project number, end client and
   item code prefix (for example GG; leave it empty if the item codes are
   just numbers) and the first item number (usually 1; e.g. 4000 if the
   client numbers from there).
   More than one kind of item code (e.g. MS for laptops, MS-M for monitors,
   MS-P or MSP for PCs)? Just enter the common start (MS). Codes that start
   with it and have more letters are found by themselves: each one is its
   own item group, numbered from 1, listed after the main prefix. The
   Final Report tab shows a gray note with the groups found, so a typo that
   became a group (like MSS05) stands out.
2. Data tab (everything the report is built from): click "Add files..." and
   choose the Blancco exports (.csv, .xlsx or .zip). You can choose several
   at once or drag them onto the box (other files dropped along with them,
   like PDFs, are skipped). Removing a file (x or Remove all) can be undone
   from the message that appears. Paste the Mac and Windows report
   lines together in "Mac and Windows reports", in any order.
3. Manual entries tab (devices the tools couldn't read: dead, BIOS locked,
   no report...): type the item number (the prefix is filled in for you),
   click "Add item" and type the details. For another item group, type its
   letters too: -M5 gives MS-M05, P5 gives MSP05. To add many at
   once, fill in "or items ... to ..." (e.g. 10 to 20) and click "Add range";
   items that already have a manual entry are skipped. A new item shows on
   the Final Report once something is typed in it. To delete several, tick their rows
   (tick one, then hold Shift and click another to tick or untick everything
   in between) and click "Delete selected items".
4. Final Report tab (check everything is right, make small corrections, then
   get the report out): every check is listed at the top. The tab shows how many there
   are: red = problems, yellow = warnings, gray = notes. Rows with a problem
   are highlighted, and clicking a check jumps to its row. Edited cells turn
   blue, and clearing a cell (Delete) goes back to the calculated value.
   Diagnostic codes (like LM or CD) work in the Diagnostics and Locked or
   Faulty cells too.

The Final Report and Manual entries tables work like a spreadsheet:
   - Click a cell, or move with the arrow keys, Tab, Enter, Home / End,
     Page Up / Page Down. Ctrl + arrow jumps to the end of the filled cells,
     or to the next filled cell (like Excel).
   - Select several cells by dragging, Shift + click or Shift + arrows.
     Click a column header to select the column, Ctrl+A selects everything.
   - Start typing to replace a cell, or double-click / F2 to change it.
     Enter or Tab saves, Esc cancels.
   - Ctrl+C copies, Ctrl+X cuts, Ctrl+V pastes (also a block of cells copied
     from Google Sheets or Excel). One copied value pasted onto a selection
     fills all of it.
   - Delete clears the selected cells, Ctrl+D fills down.
   - Ctrl+Z undoes, Ctrl+Y redoes.
   The item code columns can be selected and copied but not changed.
   Green cells are values from the Google Sheet rows (Data tab); they can
   be changed like any other cell.
5. Getting the finished report out, also on the Final Report tab. What you
   see is what you copy:
   - Filters: the arrow on each column header opens a list of that column's
     values (with a search box), like in Google Sheets or Excel. Untick
     values to hide those rows; it applies at once and the arrow turns into
     a funnel. "Search..." finds text in any column, and "Only items with
     issues" shows the rows with a check. "Clear filters" shows everything.
     Item numbers with no data yet are "(No data yet)" in the Item Lookup
     filter.
   - Columns: "Hide column" in a header's menu hides a column the Google
     Sheet doesn't have. Hidden columns aren't shown, copied or downloaded;
     "... hidden columns - Show all" brings them back. This is remembered on
     your computer.
   - "Copy all rows" copies the rows and columns shown: click the ITEM cell of
     the first item row in the Google Sheet and paste. The small arrow next
     to it has "Copy with headers". When filters are on, the button turns
     amber and says "Copy filtered rows", and the message says how many
     (e.g. "12 of 80 rows (filtered)"). Item Lookup is never copied.
   - The tabs above the table switch between the Audit Report and Locked
     and Faulty (send that list along with the report).
   - Download Excel saves both lists, as shown, in one .xlsx file.
   If problems (red) are still open, the app asks before copying or
   downloading. While filters are on, a row you change stays in view until
   you change the filters, even if it no longer matches them.

The Final Report shows a row for every item number from the first item
number up to the highest one. Numbers with no data yet get an empty (yellow)
row, so the rows line up with the Google Sheet; typing in one adds
a manual entry. The "No data yet for" warning jumps to the first one.
An item number far above the others (more than 200, e.g. GG9999 among
GG01-GG80) is most likely a typo: it gets a red check, and no empty rows are
made up to it. Fix the item number where it came from (report line, Blancco
or manual entry).
They are copied too, so the paste lines up. To leave them out, untick
"(No data yet)" in the Item Lookup filter.

If some items are already in the Google Sheet (for example BM20 was typed in
by hand):
   a. In the Google Sheet, select the rows you'd paste over (from the first
      item row down past the last filled row, same columns as the Final Report shows)
      and copy them.
   b. Paste them in "Rows already in the Google Sheet" on the Data tab. It is
      saved with the project.
   c. The sheet's values are used like any other input, but last in line:
      for every cell, Blancco, the Mac / Windows reports and manual entries
      win if they have a value; if they leave it empty, the sheet's value
      stays. Values that came from the sheet are green on the Final Report. An item
      that is only in the sheet is a normal row.
   d. You can change them like anything else: a manual entry or an edit on
      the Final Report wins over the sheet. Any problem (for example no item
      codes found) is listed on the Final Report tab.
   e. On the Final Report click "Copy all rows", click the ITEM cell of
      the first item row in the Google Sheet and paste. The sheet's values
      are included, so they aren't lost (formulas become plain values).


GOOGLE PROJECTS (THEIR ITAD REPORT LAYOUT)
------------------------------------------

Google's ITAD REPORT sheet has our data in a slightly different order.
Set "Output" to Google (top bar). The Final Report then shows their columns:
Item, S.N, Asset Tag, Type, Make, Model, CPU, RAM, Disk Capacity,
Diagnostics, Comments, Power Supply, Weight (KG). The price columns after
Weight (Value Back per asset, costs) are filled in their sheet, not here.
- It is the same data as Shuru, so an edit here also changes the Shuru
  layout, and switching back and forth loses nothing.
- Copy all rows and paste at the Item cell of the first item row. Download
  Excel gives the ITAD Report and Locked and Faulty.
- Rows already in their sheet can be pasted on the Data tab (copy Item to
  Weight (KG)).


SIMS PROJECTS (A DIFFERENT SHEET LAYOUT)
----------------------------------------

Some contractors (SIMS) want their own sheet instead of ours. The data and
the Manual entries stay exactly the same; only the output changes.

1. Set "Output" to SIMS. It is in the top bar next to the project name
   (always there).
   It is saved with the project; switch back to Shuru any time.
2. The Final Report table then shows the SIMS columns D (Item No) to T (Blancco
   Result): Category (from the device type), Model (make, model, screen,
   year), Purchase Description (CPU, RAM, disk, or n/a), our Diagnostics,
   the SIMS Diagnostic Codes, Item Remark, Weight and Blancco Result
   (Erased / Not Erased).
   - Serial No, asset tag, Diagnostics and Weight are the same as in the
     Shuru layout: changing them changes both.
   - Typing in another column (e.g. Category or Diagnostic Codes) only
     changes the SIMS output. Clear the cell to go back.
3. Diagnostic codes: each diagnostic becomes the SIMS code of the device's
   category (e.g. "Sticky kb" on a laptop is LPT107). A diagnostic with no
   SIMS code goes to Item Remark and the device gets the "see remarks" code
   (e.g. LPT172). The Final Report lists those as blue SIMS notes, so you can add them
   to the Dictionary. "Ok" is left out.
4. The Final Report has three lists (tabs above the table): Item per service
   project (paste at the Item No cell, column D, of the first item row), HDD
   (one row per data carrier serial from "S.N. Data carrier") and Locked and
   Faulty. Filters and hidden columns work the same. Download > "SIMS file"
   fills the SIMS template with the rows shown,
   so their logos, comments and Summary stay as they are; the Summary
   counts itself when you open the file. The template is
   G:\My Drive\Audit Builder\Templates\SIMS.xlsx. When SIMS sends a new
   template, empty it of data and save it over that file.
5. Rows already in the SIMS sheet can be pasted in "Rows already in the
   Google Sheet" on the Data tab (copy columns D to T), like for our sheet.

The SIMS lists are in the Dictionary (after "SIMS output:"):
- SIMS diagnostics: one row per SIMS issue. Write our diagnostics next to
  the issue they mean, separated by commas (e.g. "Sticky kb, KB sticky" next
  to keyboard defect). Capitals, spaces and dashes don't matter, and *
  stands for any word(s): "Key * defect" covers Key P defect, Key Capslock
  defect and so on. One issue
  works for every category: keyboard defect is LPT107 on a laptop and would
  be BSU107 on a PC. Writing a diagnostic on two issues gives two codes
  (BIOS locked = password protected + no audit). The first row, "Leave out",
  lists diagnostics that get no code at all (Ok). Use the search box and
  "Only issues with our diagnostics" to find your way in the list.
- SIMS codes: all SIMS codes per category (from their template), with a
  category filter and search.
- SIMS categories: which SIMS category each of our device types is, and,
  when it's different, which category's codes it uses (Switch uses Network
  Switch codes, loose disks use Data Carrier codes).


SAVING AND SHARING PROJECTS
---------------------------

- The app keeps your current work automatically, so closing the window by
  accident doesn't lose anything. That copy only exists on your computer
  and in that browser, though. (A very big project may not fit in the
  browser's copy: then a red message says so, with a "Save now" button.
  Keep that project saved to its file.)
- A new project is saved by itself as soon as you click Save in Project
  setup (when the Audit Builder folder is connected), the same way as below,
  so auto-save keeps it from the first minute.
- File > Save project (or Ctrl+S): the first time, it saves the project file
  straight into G:\My Drive\Audit Builder\Projects, named after the end
  client and project number (e.g. Acme_SHR11734.audit.json). If a file with
  that name is already there, it asks whether to replace it. (If the Audit
  Builder folder isn't connected, it asks where to save instead.)
  After that it saves over the same file without asking. The top bar shows
  which file you're saving to.
- Auto-save: once the project has a file (saved once, or opened from a
  file), every change is saved to it by itself a few seconds later. The top
  bar shows "Saving..." and then "Saved". Ctrl+S still saves right away.
- After reopening the browser, the browser needs one click before it lets
  the app edit the file again: the top bar shows "Not saved - click to save".
  Click it (or press Ctrl+S) and click Allow (or "Edit file") in the small
  message. After that, auto-save carries on by itself.
- File > Save as... (Ctrl+Shift+S) asks for a file name and place (it starts
  in the Projects folder). That file is used from then on.
- File > Open... lists the projects in the Projects folder, so you pick one
  in the app: shared projects first, then project files (newest first).
  Type in the search box to find one. "Browse..." opens a file from
  somewhere else. Opening a project file makes it the file Save updates.
- Google Drive syncs the Projects folder, so everyone can open and continue
  each other's projects. (This needs edit access to the shared folder; if
  saving there fails, ask Tomer to give you Editor access.)
- A project file is for one person at a time: if two people open the same
  file and save, their changes don't merge. To work on a project together
  at the same time, share it instead (see below).
- An old Audit.xlsm can be opened with Open... > Browse... too.


WORKING ON A PROJECT TOGETHER
-----------------------------

Two or more people can work on the same project at the same time, each on
their own computer. Everyone needs the Audit Builder folder connected (the
same one as for the shared Dictionary).

- To start: open or set up the project, then choose File > Share project...
  The app asks your name once (use the same name on every computer, and a
  different name from your coworkers). You are the one who shared it.
- To join: File > Open... and click Open next to the project under
  "Shared projects".
- Each person adds their own Blancco files and report lines on the Data tab.
  Everyone's are added together; what the others added is listed under
  yours with their name, and only they can remove it.
- Manual entries, Final Report edits and the Google Sheet rows are shared: anyone
  can change them, and everyone sees the change.
- There is no need to press Save. The top bar shows the status, like Google
  Sheets: "Saving..." while your changes are being saved, then "Saved -
  checked 3 s ago" (when the app last looked for your coworkers' changes).
  Hover over it to see when each coworker last changed something.
  "Not saved" (red) or "Not connected": click it to try again or
  to connect the folder. Your changes are kept on your computer until then.
- Your coworkers' changes come in by themselves, without reloading: the app
  checks every 5 seconds, once Google Drive has synced them (usually within
  seconds, at most about a minute). A message says what came in (e.g.
  "Dana updated GG04, GG05" or "Avi joined the shared project") and those
  rows flash for a moment. While you're typing, it waits until you pause.
- "Shared - 3 people" in the top bar shows who is working on the project
  and what each has added.
- If two people change the same cell at the same moment, the newest change
  is used and a gray note on the Final Report says what the other person typed.
  Typing the right value in that cell again removes the note.
- Ctrl+Z only undoes your own changes.
- Only the person who shared the project can change its settings (project
  number, client, prefix, first item number, output).
- File > Save as... saves a copy of everyone's work together as a normal
  project file, e.g. to keep at the end.
- File > Leave shared project... stops working on it on this computer. Your
  work stays in the shared project, and you can open it again later.
- Shared projects are kept in G:\My Drive\Audit Builder\Projects, one folder
  per project with one file per person. Don't edit or move these files.


SHARED DICTIONARY AND RULES
---------------------------

Everyone shares two files in the Audit Builder folder on the Drive:
- Models\models.json: the Dictionary (Settings > Dictionary...): models, make names,
  type mapping, weights, model cleanup, diagnostic codes and the SIMS lists. "Make names"
  turns the make the tools report into the one in the report, e.g.
  "Dell Inc." into "Dell". "Models" turns a model ID from the Mac or Windows
  reports or the Blancco export (e.g. MacBookPro15,1) into its name (Pro A1990)
  and fills in Screen and Year.
- Config\config.json: the rules the report is built with (battery grades,
  how Blancco comments are read, which checks show on the Final Report, column
  headers...), so everyone's report comes out the same.

Connect once (the browser only lets the app use files you picked yourself):
click "Connect folder..." in the yellow bar under the tabs and choose the
folder G:\My Drive\Audit Builder. The browser asks to let the app view and
edit files in it: allow it. The app then finds both files by itself.

After that:
- The app loads both every time it opens. Nothing more to do.
- After restarting the browser, a yellow bar may ask for your OK to load
  them. Click "Load shared files". If the browser offers "Allow on every
  visit", choose it and it won't ask again.
- Any change you make in the Dictionary is saved to the shared file, and
  coworkers get it the next time they open the app or switch back to it.
- If you and a coworker change the Dictionary at the same moment, the app
  keeps their version and asks you to redo your last change.

If the Dictionary window says "Not shared", your changes stay on your computer
only. Connect the folder as above.

Settings > DevMode... is for the person who maintains the rules and asks for
a password.


MICROSOFT BIOS PASSWORDS (Tools menu)
-------------------------------------

For Microsoft devices that are BIOS locked: Microsoft sends a file like
BulkBiosPasswordDetails-29065708.txt with the asset tag and password(s) of
each device.

1. Open the project, then Tools > Microsoft BIOS passwords. This opens the
   BIOS passwords tab (next to Final Report).
2. Click "Load password file..." (or drop the .txt file on the tab).
   From then on the tab stays there for this project: jump to it with Alt+4
   and back with Alt+1 / Alt+2 / Alt+3. Your search and the selected device
   stay as they were.
3. The list shows every asset tag in the file with its item number, S.N.
   and device from the project, items first (by item number), then asset
   tags that aren't in the project. Some devices have more than one
   password; each gets its own column.
4. Click a device (or move with the arrow keys) and its password appears
   as a QR code on the right, ready to scan into the BIOS. "Copy" copies
   the password.
5. Search finds an item, asset tag or S.N.; "Only devices in this project"
   hides the rest. "Copy with headers" and "Download .xlsx" give you the
   list as a sheet.
A yellow note lists items that are BIOS locked in the project but have no
password in the file.
The password file is saved with the project (also in a shared project, where
everyone sees it; the newest file anyone loaded is used), so you only load it
once. "Remove" takes the passwords out of the project.


SHARED FILES (Tools menu)
-------------------------

A place to share any file with everyone (price lists, guides, templates...):
the folder G:\My Drive\Audit Builder\Shared Files on the Drive. The app makes
it the first time it's used.

1. Tools > Shared Files lists the files there, newest first: who added each
   one, its size and when it last changed. Search finds a file by name.
2. Add files...: choose one or more files, or drop them on the window. If a
   file with the same name is already there, the app asks: Replace (the new
   one overwrites it), Keep both (the new one gets a number, e.g.
   "Guide (2).pdf") or Cancel.
3. Download saves a copy to your computer (usually the Downloads folder).
4. The x deletes a file for everyone (after asking). Google Drive keeps
   deleted files in its Trash for 30 days, so a mistake can be undone there.
"Added by" uses the same name as shared projects (asked once). A file put in
the folder or changed outside the app shows no name. The .audit-builder
folder inside Shared Files holds those names; leave it there.
The Audit Builder folder needs to be connected (like for File > Open).


PDF MERGER (Tools menu)
-----------------------

Merges PDFs (e.g. the wiping reports) into one PDF file.

1. Tools > PDF merger. Click "Add files..." or drop files on the window:
   PDFs, or .zip files with PDFs in them (also in folders inside the zip).
   Other files are skipped; the message says which.
2. The window shows how many PDF files were found and lists them in the
   order they will be merged: by file name, numbers counted as numbers
   (GG2 before GG10). The x leaves a file out; "Remove all" empties the list.
3. "Merge ... PDFs..." asks for the name of the merged file, filled in
   as WipingReports-<project number> (e.g. WipingReports-SHR11734). Change
   it if you like, then "Merge and download": the browser saves it like any
   download (usually to Downloads).
A file that isn't a real PDF (or is damaged) is left out, and the message
says which. The files stay in the window while the app is open; they are
not saved in the project.
